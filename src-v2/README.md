# Карьер · фронтенд v2 (Спринт 1)

Новый интерфейс: **React 18 + TypeScript + Vite + Tailwind**, тёмная тема из
`docs/03-ui-ux.md`. Старый `src/` не тронут.

## Запуск

```powershell
cd C:\karier\src-v2
npm install
npm run dev          # http://localhost:5174
```

Vite проксирует `/api` на `http://127.0.0.1:8001`, поэтому cookie с refresh-токеном
работают как same-origin — без CORS и без токенов в `localStorage`.

Бэкенд должен быть поднят заранее (см. `backend-v2/README.md`).

## Карта (Спринт 2)

* `Leaflet` + `CRS.Simple`, подложка `public/karier-map.jpg` (2048×1152 px → 1024×576 м).
* Координаты объектов — метры: `[y, x]` в Leaflet, `x` — восток, `y` — север.
* Маркеры — `divIcon` с иконкой и цветом типа, обводка по статусу.
* Шторка (`components/BottomSheet.tsx`) — 46vh/88vh, тянется за ручку.
* Админ: кнопка «＋ Объект» включает режим, клик по карте подставляет координаты.
* `scripts/dev-screenshot.mjs` — скриншот интерфейса через headless Chrome (CDP),
  полезен для проверки карты без ручной работы:

```powershell
node scripts/dev-screenshot.mjs http://127.0.0.1:5174/ C:\karier\.tmp\map.png 390 844
```

## Карта и схема (Спринт 3)

* Переключатель **«Карта / Схема»** в верхней панели.
* Схема — React Flow + dagre: раскладка сверху вниз, подписи связей (фидер/марка кабеля),
  пунктир для разомкнутых, фиолетовый для перемычек. Чанк схемы грузится лениво.
* Клик по узлу схемы открывает ту же карточку, что и маркер на карте.
* «🔗 Соединить» (админ): порт OUT → порт IN → марка/длина → `POST /api/links`.
* Внутренняя схема ПС/БКРУ: список ячеек с переключением и заземлением.
* Документы объекта: вкладка в карточке, просмотр в iframe, «Скачать офлайн» в IndexedDB,
  открытие без сети с пометкой «Офлайн-версия».

## Фото, обходы, QR (Спринт 4)

* Съёмка: `input type="file" capture="environment"` → EXIF (`exifr`) → гео устройства → водяной знак на canvas
  (дата, координаты, автор, код объекта) → JPEG 1600 px.
* Офлайн-очередь (`lib/outbox.ts`, IndexedDB): обход, отметки, дефекты и фото уходят при появлении сети;
  временные id связываются с серверными через `idmap`.
* QR: `qrcode.react` → ссылка `/asset/{id}`, печать наклейки; сканер `html5-qrcode` грузится лениво.
* Тесты: `npm test` — строки водяного знака и честность координат (vitest).

## Синхронизация и перемещения (Спринт 5)

* Очередь IndexedDB (`lib/outbox.ts`) + push (`POST /api/sync/push`) для статусов и `POST /api/assets/{id}/move` для перемещений.
* Конфликты LWW: экран `/sync` показывает очередь, конфликты, курсор `change_log` и ошибки.
* Перемещение «кукушки»: кнопка 🚚 в карточке → клик по карте → причина → очередь; история перемещений рисуется пунктиром.
* Service Worker (`public/sw.js`): кэш оболочки и GET-API, Background Sync `karier-outbox`.

## Как устроен доступ на клиенте

* `AuthProvider` при старте делает `POST /api/auth/refresh` по cookie и
  восстанавливает сессию — пользователь не видит экран входа после перезагрузки.
* Access-токен хранится **только в памяти** (`lib/api.ts`), в `localStorage`
  ничего не пишется — XSS не даёт долговременного доступа.
* `RequireAuth` закрывает разделы, `RequirePermission` прячет админские пункты.
  Это UX-удобство: настоящая проверка прав — на сервере.

## Сборка

```powershell
npm run build        # tsc -b && vite build → dist/
```

Проверено: сборка проходит, `dist/index.html` + `assets/*.js|css` собираются.

> В этой песочнице `npm run dev` и `npm run build` требуют запуска вне ограничений
> (esbuild стартует отдельным процессом). На обычной машине это не проблема.
