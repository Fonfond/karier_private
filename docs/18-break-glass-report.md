# Аварийный доступ (break glass) — отчёт

Ветка: `feature/sprint-15-break-glass` · Дата: 08.11.2026

## Что сделано

| Блок | Детали |
|---|---|
| БД | `auth.employees.is_break_glass` (миграция `0009_break_glass`) |
| Сервис | `app/services/break_glass.py`: выпуск, ротация, блокировка, ASCII QR |
| Скрипты | `seed_break_glass.py` (создание), `reset_break_glass.py` (ротация, `--disable`) |
| Аудит | действия аккаунта пишутся с `payload.break_glass = true` |
| Защита | API запрещает block / dismiss / permanent delete / смену роли (`employee.break_glass_protected`) |
| UI | бейдж «аварийный», кнопки действий скрыты |
| Документация | раздел «Аварийный доступ» в корневом README |

## Как устроено

* Табельный `000000`, роль `admin`, `is_break_glass = true`.
* Пароль — 28 символов из алфавита без похожих символов (`Il1O0`), генерируется `secrets`.
* TOTP-секрет — `pyotp.random_base32()`, шифруется AES-256-GCM (как у остальных 2FA).
* При ротации: новый пароль и секрет, сброс `last_counter` (защита от повторного использования кода), отзыв всех сессий.
* `seed_break_glass.py` печатает пароль, секрет, `otpauth://`, ASCII QR и инструкцию «распечатать и положить в сейф».

## Ограничения

* Пароль и секрет не сохраняются ни в файл, ни в БД — только печать. Потеря конверта означает ротацию.
* Метка `break_glass` ставится в payload аудита; отдельного фильтра в UI пока нет — выборка по табельному `000000`.
