# Комплектность включается автоматически для типов с подтипами

## Что изменилось

* Если у типа есть **активные подтипы**, он автоматически считается комплектным:
  `is_composite = true`, а состав (`composite_template`) собирается из подтипов.
* При добавлении нового подтипа родительский тип обновляется сам.
* В редакторе типов раздел «Комплектное оборудование» теперь показывается для любого
  типа с подтипами (и чекбокс уже включён), список ячеек подставляется автоматически.
* Неактивные/удалённые подтипы в состав не попадают (иначе размещение падало
  с «Неизвестный тип объекта»).

## ПС 35-6

Тип `ps_35` теперь комплектный, состав:

`ячейка 7к`, `ячейка 5`, `ячейка 16`, `ячейка 21`.

На карте: «Комплект» → `ПС 35-6 кВ Карьер` → «Указать место» — создаётся ПС
как один объект с 4 ячейками, на схеме — рамка.

Проверка: `POST /api/composites/place` → 200, 4 дочерних ячейки; тестовый комплект
удалён.

## Важно

В текущей базе сейчас есть только комплект `БКРУ-1` с ячейками (создан вами через
карту). Объект `PS_35-2` и фидеры в базе отсутствуют — если вы их удалили, ПС можно:
* поставить заново кнопкой «Комплект» (появится с ячейками), либо
* вернуть прежние объекты из бэкапа `backups/karier_user_data_20261110.dump`
  и присоединить к ПС через `/api/composites/{id}/attach`.

## Ограничения

1. Состав автоматически включает **все активные подтипы**; убрать отдельный подтип
   из комплекта можно только вручную в редакторе типа (снять количество).
2. У типа `ps_35_6_kv` подтипы неактивны, поэтому состав пуст — это дубль типа,
   его можно удалить.
3. Присоединение уже существующих ячеек к комплекту — пока через API.
