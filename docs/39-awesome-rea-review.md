# Обзор Awesome-REA: что может пригодиться проекту «Карьер»

Источник: https://github.com/reacher-z/Awesome-REA (MIT), сайт https://awesomerea.org/.
Просмотрены README и каталог; на момент обзора — 5 191 ресурс, 4 025 кейсов, 417 статей.

## 1. Что это такое

Каталог инструментов и кейсов по **обратной разработке** (Reverse Engineering Anything)
в шести областях:

| Раздел | Содержание |
|---|---|
| Website | деобфускация JS, восстановление API, разбор бандлов, source maps |
| Game | декомпиляция игр, парсеры реплеев, эмуляторы |
| App | Android/.NET/JVM: JADX, Frida, apktool, ILSpy |
| Native Binary | дизассемблеры, декомпиляторы, диффинг |
| Firmware / Hardware | извлечение и анализ прошивок |
| Protocol | форматы обмена, разбор пакетов, захват трафика |
| Agents & MCP | MCP-серверы и агентные обвязки для RE |
| Papers | 417 научных статей |

Плюс машиночитаемые данные: `catalog.json`, `llms.txt`, JSON/CSV API, датасет на Hugging Face.

**К нашему домену (электрика, ПУЭ, ГОСТ, схемы) отношения не имеет** — ни справочников
оборудования, ни нормативов, ни расчётов. Полезны только инструменты разработки и
интеграций.

## 2. Что реально может пригодиться

### A. Проверка и автоматизация интерфейса (QA)

| Инструмент | Зачем нам | Оценка |
|---|---|---|
| **Playwright MCP** | агентные прогоны UI: формы, мобильная вёрстка, сценарии «создать тип → объект → связь» без ручных скриптов | 0,5–1 день, польза средняя |
| **Chrome DevTools MCP** | живые проверки страницы, сеть, трассировки производительности (у нас есть свои headless-скрипты — это их замена) | 0,5 дня, средняя |

Сейчас аудит мобильной вёрстки и скриншоты делаются самописными скриптами на CDP —
MCP-серверы позволили бы делать то же через агента, но выигрыш не революционный.

### B. Развитие API и MCP-сервера

| Инструмент | Зачем нам | Оценка |
|---|---|---|
| **Spectral** | из записанного трафика генерирует OpenAPI 3.1 и MCP-инструменты — можно быстро покрыть MCP-инструментами остальные эндпоинты (сейчас 5: assets, links, move, topology check) | 1–2 дня, польза высокая |
| **mitmproxy2swagger** | восстановление OpenAPI из трафика; у FastAPI уже есть `/openapi.json`, поэтому ценность низкая | не нужно |
| **Burp Suite MCP Server** | проверка безопасности JWT/cookies/ролей, повтор запросов, поиск IDOR | 1 день, польза средняя (аудит перед продом) |

### C. Дизайн и прототипы

* **Dembrandt** — извлекает дизайн-систему сайта (цвета, типографика, отступы, тени, брейкпоинты).
  У нас уже есть токены и тёмная тема; может пригодиться для аудита консистентности.
* **screenshot-to-code** — генерация вёрстки по скриншоту. Низкая ценность: UI уже готов,
  риск «сгенерировать заново и сломать».

### D. Инженерные данные и устройства (потенциально)

В каталоге есть раздел **Protocol** (720 записей) и **Firmware** — инструменты разбора
проводовых протоколов, CAN, serial, BLE. Для будущего подключения телеметрии
(уровень топлива, моточасы с контроллеров ДГУ/мачт) могут быть полезны общие
инструменты захвата и разбора протоколов.

Оговорка: в просмотренном фрагменте каталога **не встретилось** Modbus, OPC UA,
IEC 61850, SCADA — то есть готовых промышленных интеграций там нет, только общая
RE-обвязка. Если пойдём в телеметрию, проще взять специализированные библиотеки
(pymodbus, asyncua), а не RE-инструменты.

### E. Как оформлен каталог (идея, а не код)

`llms.txt` + `catalog.json` + JSON Feed + версионирование данных — хороший образец
машиночитаемой документации. Можно повторить для нашей документации и MCP:
сгенерировать `docs/catalog.json` со списком отчётов, API-эндпоинтов и MCP-инструментов.

## 3. Что точно не стоит брать

* Game/App/Native инструменты (Frida, JADX, IDA, декомпиляторы) — к продукту отношения
  не имеют, часть относится к двойному назначению; в проект не тащить.
* Деобфускаторы JS (webcrack, humanify) — нужны, только если будем разбирать чужой
  фронтенд; у нас свой исходный код.
* Почти весь раздел Firmware — только для железа, не для веб-системы.

## 4. Рекомендация

Если брать что-то одно — **Spectral** для расширения MCP-сервера (наибольшая польза
при нашей архитектуре). Если два — плюс **Playwright MCP** для агентной проверки UI.

Ориентировочный порядок:

1. **Spectral** — 1–2 дня: покрыть MCP-инструментами реестр, типы, отчёты.
2. **Playwright MCP** — 0,5–1 день: сценарии проверки форм и мобильной вёрстки.
3. **Burp MCP** — по желанию, перед публикацией: аудит доступа по ролям.
4. **Dembrandt** — опционально, аудит дизайн-токенов.

## 5. Риски

* Все инструменты — сторонние, со своими лицензиями; использовать только в разработке,
  не включать в поставку.
* MCP-серверы запускают локальный код и имеют доступ к браузеру/трафику — доверять
  только проверенным, ставить в отдельный профиль.
* Каталог обновляется автоматически (последний скан 2026-11-09), часть записей
  не проверена вручную — перед использованием смотреть первоисточник.
