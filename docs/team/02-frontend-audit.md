## 0. Краткое резюме

1. **PWA-обещание «работает офлайн» сейчас не выполняется на холодном старте:** при отсутствии сети `AuthProvider` сбрасывает сессию и показывает экран входа (`src/auth/AuthProvider.tsx:36-43`).
2. **В прод уходят sourcemap’ы:** 3 файла `.js.map` на 5,19 МБ — 68 % от всех 7,58 МБ `dist/`, они публично доступны и раскрывают исходники (`src-v2/vite.config.ts:23`).
3. **Service worker кэширует авторизованные GET-ответы без привязки к пользователю и без TTL** — данные одного сотрудника доступны другому на общем планшете; кэш растёт бесконечно (`public/sw.js:59-79`, `33-40`).
4. **Карта «прыгает» к исходному виду при каждом ре-рендере:** `bounds` пересоздаётся в теле `MapView`, а `FitBounds` зависит от его идентичности (`src/components/map/MapView.tsx:62-92,114-117`). Достаточно выбрать объект после зума — вид сбрасывается.
5. **Нет ни одного ErrorBoundary:** любая ошибка рендера в любой странице даёт белый экран без выхода (в `src/` нет `ErrorBoundary`/`componentDidCatch`).
6. **Офлайн-очередь синхронизируется без мьютекса** (`src/lib/useOutbox.ts:54-61`, `src/lib/sync.ts:144-176`): параллельные `syncOutbox()` могут дважды отправить один и тот же `inspection_create`/`defect`/фото.
7. **Код не разделён по маршрутам:** все страницы импортированы статически (`src/App.tsx:5-20`), начальный JS — 623 КБ raw / 187 КБ gzip, включая Leaflet, `exifr`, админские разделы.
8. **Системный дефицит доступности:** на 57 файлов и ~13 000 строк — всего 11 `aria-*`/`role=`, из 24 модальных контейнеров `role="dialog"` есть ровно у одного, `Escape` закрывает модалки только в 2 местах (и это не модалки), контраст `ink3` — 4,15–4,37:1 при кегле 10–12 px (ниже AA 4,5:1), `maximum-scale=1.0` запрещает пинч-зум.

Позитив, который стоит сохранить: строгий TypeScript (`strict`, `noUnusedLocals` — `tsconfig.json:15-18`), токен доступа только в памяти + refresh в httpOnly-cookie (`src/lib/api.ts:111-120`), security-заголовки и CSP в `vercel.json`, lazy-загрузка тяжёлых `html5-qrcode` и React Flow (`src/components/AppShell.tsx:11-13`, `src/pages/MapPage.tsx:16-18`), аккуратные мобильные правила (16 px в полях против iOS-зума, 44–48 px кнопки — `src/index.css:209-229`), `aria-label` у кнопок зума карты.

### 2.2 Карта (Leaflet)

- **Сброс вида при любом ре-рендере.** `const bounds = L.latLngBounds(...)` создаётся в теле `MapView` при каждом рендере (`MapView.tsx:114-117`), а `FitBounds` имеет `bounds` в зависимостях эффекта и делает `map.setView(...)` (`MapView.tsx:62-92`). `MapView` не мемоизирован, поэтому любой ре-рендер `MapPage` (выбор объекта, открытие шторки, ошибка, `draft`, `hint`) пересоздаёт `bounds` → карта возвращается в «обзорный» вид. Пользователь зумится к КТП, тапает маркер — и теряет масштаб. Это самая заметная UX-регрессия карты.
- **Иконки маркеров создаются заново для каждого маркера на каждый рендер:** `markerIcon(asset, …)` внутри `assets.map` (`MapView.tsx:138-162`, фабрика `30-43`). Каждый вызов — новый `L.divIcon` с HTML-строкой; Leaflet вынужден переустанавливать иконки. Нет ни `React.memo`, ни `useMemo`-кэша по `(typeId, status, selected)`.
- **Нет кластеризации и нет `preferCanvas`:** все объекты — отдельные DOM-маркеры в SVG/HTML-слоях (`MapContainer`, `MapView.tsx:121-133`). При нескольких сотнях объектов страница «тяжёлая» на бюджетных планшетах; при этом API реестра вообще не умеет пагинацию (`src/lib/gis.ts:273-288`) и всегда отдаёт всё.
- **Полилинии связей** создаются на каждый рендер (`MapView.tsx:170-188`), `positions` приходит из `MapPage` как объект, собранный инлайн в разметке: `Object.fromEntries(assets.filter(...).map(...))` (`MapPage.tsx:679-683`) — O(n) на каждый рендер плюс новая ссылка каждый раз.
- **Превью соединения** обновляет React-состояние на каждое `mousemove` (`MapView.tsx:214-223`) → ре-рендер компонента и перерисовка полилинии на каждое движение мыши.
- **Кнопка «Моё положение» — пустышка:** и в успехе, и в ошибке геолокации вызывается `map.fitBounds(bounds)` (`MapView.tsx:264-271`). Пользователь ждёт центрирования на себе и не получает ничего.
- **Подложка** — JPG 1,06 МБ без `srcset`; для WebP/AVIF-варианта это ~200–300 КБ (экономия 0,7–0,8 МБ на первую загрузку в поле).

### 2.3 Редактор схемы (React Flow)

- **Полная пересборка узлов и связей при любом переключении режима или выборе.** Эффект `SchemaView.tsx:1026-1067` собирает все `nodes` (включая `graph.blocks.find` для каждого узла, строка 1041 — O(n·m)) и все `edges` (`buildEdges`, 531-582) и имеет в зависимостях 18 значений, среди которых `jumperMode`, `cellLinkMode`, `cableMode`, `activeConnection`, `jumperFirst`, `cellLinkFirst`, `cableFrom`, `selectedId`-производные. Переключение любого флага = полный rebuild всех узлов.
- **Второй эффект пересобирает `data` всех узлов при смене выделения** (`SchemaView.tsx:1070-1085`): выбираем один узел — React Flow перерисовывает все, потому что `data` у всех новые объекты.
- **Дагре-раскладка считается всегда, даже когда все позиции сохранены:** `nodePositions` безусловно вызывает `dagrePositions` (`SchemaView.tsx:519-529`), хотя результат нужен только узлам без `schema_x/schema_y`. На большой схеме это синхронный блокирующий расчёт при каждом изменении `graph`.
- **`AssetNode` не мемоизирован** (`SchemaView.tsx:136`), а внутри — измерение всех ячеек блока через `getBoundingClientRect` в `useLayoutEffect` (`147-188`) с `requestAnimationFrame`-повторами и глобальным `resize`-листенером **на каждый узел**. Десятки раскрытых блоков = десятки листенеров и layout-thrash.
- **Перетаскивание узла** в `onNodeDrag` перебирает все узлы на каждое движение (`SchemaView.tsx:1802-1818`) — O(n²) на drag.
- **Таймеры фокуса не очищаются:** `focusAsset` ставит `setTimeout` на 500 и 1400 мс и не сохраняет id (`SchemaView.tsx:663-681`); после размонтирования они всё равно дёрнут `fitView`.
- **Позиции DXF мемоизированы** — `1588-1602`, это правильно.

### 2.4 Списки, реестр, refetch

- **Реестр рендерит оба представления одновременно:** мобильные карточки (`RegistryPage.tsx:336-404`, `md:hidden`) и десктопную таблицу (`406-501`, `hidden md:block`) — то есть на телефоне в DOM всё равно живут все строки таблицы с тремя кнопками в каждой, а на десктопе — все карточки. При 400 объектах это ~800 элементов и >2 400 кнопок. Ни виртуализации, ни пагинации (`gis.ts:273-288` не поддерживает limit/offset).
- **Поиск в реестре перерисовывает весь список на каждый символ** (`RegistryPage.tsx:244-250` → `rows` useMemo `72-101`); без `useDeferredValue`/debounce. На телефоне ввод ощутимо лагает.
- **Поиск сотрудников бьёт в API на каждый символ и без защиты от гонки:** `load` зависит от `search` (`EmployeesPage.tsx:117-128`), ответы могут прийти не по порядку и перезаписать актуальный список старым.
- **Нет клиентского кэша/дедупликации:** каждая страница при монтировании заново тянет `/api/assets`, `/api/asset-types`, `/api/map/layers/active` (`MapPage.tsx:131-157`, `RegistryPage.tsx:43-62`, `AddToSchemaPanel.tsx:50-78`). Переход «Реестр → Карта → Реестр» = 6+ повторных запросов.
- **`MapPage.refresh()` после каждой мутации делает `load()` (3 запроса) + `loadGraph()` (1 запрос)** (`MapPage.tsx:167-170`; вызовы на `355, 369, 558-568, 589, 610, 641`). Создание объекта = 4 сетевых запроса на обновление.
- **Дашборд опрашивает сервер каждые 60 с без учёта видимости вкладки** (`DashboardPage.tsx:131`) — фоновый трафик и работа батареи в поле.
- **`SyncPage` перезапрашивает конфликты и состояние при каждом изменении `pending`** (`SyncPage.tsx:47-49`), т.е. после каждой синхронизации — ещё два запроса.

### 2.5 «Тяжёлые вычисления без useMemo» (сводно)

`MapView.markerIcon` и `historyPoints` (30-43, 118), `MapPage.positions` (679-683), `AssetNode`-фильтры `busbars/cells` и `jumperCells` (193-199), `graph.blocks.find` в цикле (1041), `Donut`/`Bars` дашборда (пересчёт на рендер, но дёшево). ## 3. Надёжность UI

### 3.1 Аутентификация и сеть

- **Офлайн-старт = выход из приложения.** Bootstrap в `AuthProvider` при любой ошибке `api.refresh()` (включая `TypeError: Failed to fetch` при отсутствии сети) удаляет `karier-session` и оставляет `user = null` (`src/auth/AuthProvider.tsx:29-44`, catch на `39-42`); `RequireAuth` уводит на `/login` (`src/auth/guards.tsx:10-11`). Данные при этом могут быть в кэше SW — но приложение их не покажет. Для заявленного офлайн-режима это блокер.
- **Нет таймаутов запросов.** `request()` вызывает `fetch` без `AbortSignal`/таймаута (`src/lib/api.ts:122-154`) — «зависший» запрос оставляет экран в состоянии загрузки навсегда, без возможности прервать. `AbortController` в проекте не используется вовсе (0 вхождений).
- **Обновление токена при 401 не дедуплицируется.** Параллельные запросы с протухшим access-токеном одновременно вызывают `tryRefresh()` (`api.ts:137-140, 156-165`); защита `refreshInFlight` есть только у `api.refresh()` (`188-202`). Два одновременных `POST /auth/refresh` одним и тем же refresh-cookie — это ротация «двумя запросами» и потенциальное срабатывание серверной защиты от повторного использования токена (в аудите бэкенда есть событие `auth.refresh.reuse_detected`).
- **`window.open` после `await`** в `openExport` (`src/lib/dashboard.ts:51-57`) — на iOS Safari всплывающее окно блокируется, кнопки «Excel»/«Паспорт PDF» могут молча ничего не делать.

### 3.2 Ошибки, загрузка, пустота

- **Нет ErrorBoundary** (0 вхождений `ErrorBoundary`/`componentDidCatch`). Ошибка в рендере любой страницы (например, `data.assets.by_status` при неожиданном ответе) обрушивает всё дерево — пользователь видит пустой экран.
- **Нет единого паттерна «загрузка / пусто / ошибка».** Примеры:
  - `RegistryPage` вообще не имеет состояния загрузки: до ответа показывает «Показано 0 из 0» и «Ничего не найдено» (`RegistryPage.tsx:43-62, 333, 403`).
  - `CablesPage` — то же (`CablesPage.tsx:32-44`).
  - `DefectsPage` — то же (`DefectsPage.tsx:32-47`).
  - `DocumentsTab` показывает «Документов пока нет» до прихода списка (`DocumentsTab.tsx:119-126`).
  - `ProfilePage` глушит ошибку списка сессий: `.catch(() => setSessions([]))` (`ProfilePage.tsx:41`) — пользователь видит «нет устройств» вместо ошибки.
  - `InspectionPage.load` ловит всё без сообщения (`InspectionPage.tsx:55-57`) — при 500/401 пользователь видит «Обход не начат».
- **Ошибки показываются дважды на карте:** встроенный `Alert` в верхней панели (`MapPage.tsx:814-818`) и фиксированный «тост» (`840-845`) одновременно дублируют один текст.
- **Поля валидации с сервера не отображаются:** `normalizeProblem` собирает `fields` (`api.ts:40-58`), `ApiError.fields` (`68-74`) — но ни один компонент не читает `.fields` (grep: 0 использований вне `api.ts`). Пользователь получает общий текст «Проверьте параметры связи — поле: сообщение», без подсветки конкретного поля; `aria-invalid`/`aria-describedby` не используются нигде.
- **Ошибки не привязаны к сроку жизни:** `setStatus`/`setError` в схеме (`SchemaView.tsx:1764-1772`) не сбрасываются автоматически и висят на экране после устаревания.
- **Молчаливые `catch`:** `SchemaView.tsx:717-726` (блоки/легенда — при ошибке просто пусто), `1087-1091` (рамка), `MapPage.tsx:208` (`moveHistory`), `DocumentsTab`/`PhotosTab` — частично.

### 3.3 Гонки и сохранение

- **`AssetSheet` не отменяет загрузку при смене объекта:** `load()` — `Promise.all` из трёх запросов, запускается эффектом при смене `assetId` (`AssetSheet.tsx:64-90`) без признака «этот ответ уже не нужен». Быстрое переключение «родитель → ребёнок» может показать данные предыдущего объекта.
- **`MapPage.openAsset`** запрашивает детали и историю перемещений без защиты от гонки (`MapPage.tsx:178-209`): история предыдущего объекта может перезаписать текущую.
- **Сохранение раскладки схемы без `base_version`:** `gisApi.saveSchemaLayout(items, ports)` (`src/lib/gis.ts:407-415`, вызов `SchemaView.tsx:1103-1131`) отправляет абсолютные позиции всех узлов. Два администратора, двигающие схему одновременно, молча затирают друг друга; предупреждения и мержа нет.
- **Правки карточки** (`AssetSheet.saveEditor`, `107-129`) тоже без версии — lost update при параллельном редактировании.
- **Несохранённые правки раскладки теряются без предупреждения:** флаг `dirty` объявлен, но значение не читается (`const [, setDirty] = useState(false)` — `SchemaView.tsx:609`; вызовы `1061, 1154, 1163, 1202`), `beforeunload`-хука нет. Закрыл вкладку — двигал зря.
- **Повторная отправка операций:** `markItem` в обходе на каждый тап делает `enqueue` + `sync()` (`InspectionPage.tsx:139-146`), кнопки не блокируются; два быстрых тапа = два `inspection_item`, а при совпадении с фоновым циклом (`useOutbox.ts:54-61`) — дубли и в `inspection_create`/`defect`.
- **`syncOutbox` не имеет мьютекса** (`sync.ts:144-176`): вызывается из `useOutbox` (интервал 15 с и событие `online`), из `StateControls` (`StateControls.tsx:80`), из `InspectionPage` (`145, 200, 213`), из `MapPage` (`609`). Две параллельные итерации читают один и тот же список операций и могут отправить одну операцию дважды; сервер дедуплицирует только `syncApi.push` (по `op_id`), а REST-эндпоинты обходов/дефектов/фото — нет.
- **«Залипшие» операции не разрешаются:** после 5 попыток операция пропускается (`sync.ts:156-159`), но остаётся в IndexedDB, продолжает считаться в `pending` (`useOutbox` → бейдж «↑N» в шапке, `AppShell.tsx:102-115`) и выводится в `SyncPage` только для чтения — кнопок «повторить»/«удалить» нет (`SyncPage.tsx:101-126`).
- **Определение сетевой ошибки по тексту сообщения** (`sync.ts:165-171`: `'Failed to fetch'`) не срабатывает в Safari/iOS (`'Load failed'`) — цикл не прерывается, все операции получают `attempts += 1` и быстрее упираются в лимит 5.

### 4.2 Клавиатура и фокус

- **Модалки:** 23 из 24 не имеют `role="dialog"`, `aria-modal`, названия по `aria-labelledby`, не закрываются по `Escape`, не удерживают фокус и не возвращают его на инициатора (`RegistryPage.tsx:503-...`, `InspectionPage.tsx:329-...`, `AssetSheet.tsx:345-426`, `DocumentsTab.tsx:242-272`, `SnapshotsPanel.tsx:98`, `AddToSchemaPanel.tsx:193`, `BulkCellsDialog.tsx:69`, `PhotoDialog.tsx:65`, `QrModal.tsx:42`, `ChildrenModal.tsx:49`, `TypesPage.tsx:204`, `CablesPage.tsx:171`, `EmployeesPage.tsx:394`, `MapPage.tsx:1138,1176,1403` и т.д.). Фокус после закрытия остаётся «в никуда» — Tab начинает с начала документа.
- **Закрытая шторка остаётся доступной для Tab и объявлена модальной:** `BottomSheet` всегда рендерит `<section role="dialog" aria-modal="true">` и лишь сдвигает её трансформом (`BottomSheet.tsx:74-87`), без `inert`/`aria-hidden`/`pointer-events-none`. В `MapPage` таких шторок шесть (`957, 986, 1038, 1073, 1265, 1319`), в них — поля и кнопки. Клавиатурный пользователь и скринридер «заходят» в невидимую форму.
- **Контекстное меню схемы недоступно с клавиатуры:** открывается только `onNodeContextMenu`/`onEdgeContextMenu`/`onPaneContextMenu` (right-click, `SchemaView.tsx:1833-1844`), закрывается только кликом по полю (`1845`), нет `role="menu"`, стрелок, `Escape`, нет clamp по границам экрана (меню у нижнего/правого края уедет за экран). На планшете в перчатках right-click часто недоступен — редактирование связей/удаление узлов фактически только через мышь.
- **Узлы схемы не фокусируемы:** выбор — только `onNodeClick` (`1780`), нет `Delete`, стрелок, `Tab`-обхода; React Flow-канвас не имеет ни `aria-label`, ни описания. Единственные клавиатурные сокращения — Ctrl+Z/Ctrl+Y (`1239-1257`) и Enter/Escape в режиме полилинии (`1302-1316`).
- **Маркеры карты недоступны без мыши/тапа:** `L.divIcon` с HTML-строкой (`MapView.tsx:30-43`), у маркеров нет ни `title`, ни `tabindex`, ни текстовой альтернативы; список объектов с клавиатуры доступен только через реестр, что для «карта — главный экран» плохо.
- **Нет объявления динамики:** тосты/уведомления — обычные `<div>` (кроме `Alert`), счётчик очереди в шапке не анонсируется, статус синхронизации тоже.

### 4.4 Тач-цели, зум, ориентация

- Основные кнопки защищены: `.btn-*` на мобиле получают `min-height: 44px` (`index.css:218-222`), поля — 48 px и 16 px шрифт против iOS-зума (`209-216`), нижняя навигация — 56 px (`BottomNav.tsx:85`). Это хорошо.

Для работы в перчатках это ниже комфортного порога (44 px, собственный гайдлайн проекта в `index.css:224`).

- Длинные списки (обход — все объекты, `InspectionPage.tsx:284-324`; реестр — все объекты) без виртуализации и без «липких» фильтров.

## 8. Ограничения аудита и что передать дальше

- **Не проверялось:** реальный профиль в браузере (React DevTools/Performance), Lighthouse, размеры ответов API, фактическое количество объектов в БД, поведение на iOS/Android-устройствах. Все оценки «сколько объектов/медиа» — качественные; количественные замеры должен дать qa-runner.
- **Сборка/типизация не запускались** (по контракту это зона qa-runner). Стоит прогнать `npm run typecheck`, `npm run build` и `npx vite-bundle-visualizer` для подтверждения цифр из раздела 1.1 и проверки вывода code splitting.
- **Тестов фронтенда почти нет:** только `src/lib/dxf.test.ts` и `src/lib/photo.test.ts` (vitest). Компоненты, критичные для полевого сценария (обход, офлайн-очередь, `syncOutbox`, `sw.js`), не покрыты — рекомендую контрактные тесты на `syncOutbox` (идемпотентность/повторная отправка) и e2e на офлайн-старт.
- **Пересечения с другими участниками:** пункты F-01/F-05/F-27/F-30 касаются поведения бэкенда (идемпотентность REST-эндпоинтов, семантика refresh-токена, версии раскладки) — их стоит согласовать с аудитом бэкенда, чтобы не чинить только клиент.
- **Приоритизация для следующего цикла:** F-01…F-06 — «гигиена», их можно закрыть одним небольшим спринтом (в основном S); F-07/F-08/F-10 — отдельный спринт производительности и доступности; F-09 и F-11…F-13 (редактор схемы) — третий заход, поскольку требуют аккуратного рефакторинга `SchemaView`.
