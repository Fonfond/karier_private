## 2. Ресайз блока (NodeResizer)

### 2.1. Маркеры и минимумы

`SchemaView.tsx` (узел `AssetNodeImpl`, ветка блока):

* `NodeResizer` из `@xyflow/react` рендерится у **каждого развёрнутого блока** в режиме
  редактирования (`isVisible`, `editable = editMode && canEdit`); 4 угловых + 4 линейных
  маркера (`.react-flow__resize-control`), `minWidth={160}`, `minHeight={120}`
  (backend-минимумы 120×80, в UI запас на шапку), `maxWidth/maxHeight = 4000`.
* Размер узла живёт в `liveSize` (обновляется `onResize` на каждом шаге и `onResizeEnd`
  при отпускании) и инициализируется из `blockSizeOf(block)` — `schema_width/schema_height`
  с фолбэком на исторические `width/height`. `NodeProps.width` для этого не годится:
  React Flow отдаёт туда `measured` (0 до первого измерения) — из-за этого в первой
  итерации блок «схлопывался» в 4 px; исправлено.
* Узел при сборке графа получает `width/height` из `schema_width/height` — после полной
  перезагрузки React Flow рисует блок сохранённого размера сразу.

Скриншот **01-block-resize-handles.png**: блок БКРУ, синие угловые маркеры, у каждой ячейки
видны порты-кружки и ручка ⠿, вёрстка не «поехала».

### 2.2. Содержимое перестраивается при ресайзе

* Контент блока — flex-колонка: шапка и шины `shrink-0`, тело `min-h-0 flex-1 overflow-auto`
  (внутри — сетка `repeat(auto-fill, minmax(132px, 1fr))`).
* Пока идёт перетаскивание — ячейки абсолютные (по текущим координатам), после `onResizeEnd`
  раскладка **пересобирается**: `draggedCells`/`measuredCells` очищаются, ячейки снова
  измеряются сеткой под новую ширину (`reflowLayout`). Поэтому при 320 px — 2 колонки,
  при 500 px — 3 колонки (`cellWidthForBlock`: 146 → 157 px), текст и подписи остаются целиком.
* Ограничение по высоте: при фиксированной высоте блок скроллит тело, шапка остаётся на месте.
* Итог: 01 (320 px, 2 колонки) → 02 (500×436, 3 колонки, шапка «6 ячеек · 0 шин · обесточено»
  на месте, все подписи полные).

### 2.3. Сохранение размера и восстановление

* После `onResizeEnd` размер пишется в `savedBlockSizesRef` и попадает в автосейв:
  элемент `{asset_id, x, y, width, height}` + локальные координаты всех ячеек блока.
* `PUT /api/topology/layout` → `gis.assets.schema_width/schema_height` (контракт t1).
* 03: после `Page.navigate` (полная перезагрузка) блок открывается `data-block-width=500`,
  `data-block-height=436`, раскладка `freeform` — как до перезагрузки. Граф после reload
  читает размер из `gis.assets.schema_width/schema_height` (контракт t1), т.е. 500×436
  реально лежат в БД, а не только в памяти вкладки.
  В ответе `PUT /api/topology/layout` автосейв учитывает блок и его ячейки
  (`updated_blocks`/`updated_cells` в `SchemaLayoutOut`).

## 3. Handles на ячейках и связь через порт ячейки

### 3.1. Порты ячеек

* Внутри каждой ячейки блока (вводная/отходящая/секционная) — два `Handle`:
  `cell:<cellId>:in` (target, слева) и `cell:<cellId>:out` (source, справа).
  `isConnectable = editable && !portDrag`; в обычном режиме кружки приглушены
  (`.schema-cell-handle`, opacity .3), в редактировании — активные (`.schema-cell-handle--edit`).
* `buildEdges` (экспортирован, покрыт логикой в `SchemaView`) перерисовывает связь с вложенной
  ячейкой на **handle ячейки внутри узла блока** (`cell:<id>:in/out`), а не на порт блока —
  иначе линия «висела» бы в пустоте (ячейки не являются узлами холста). Перемычки
  внутри блока по-прежнему рисуются SVG-линиями внутри блока и не дублируются.
* Проверка соединения (`resolveConnection`) различает порт узла и порт ячейки; для ячейки
  направление задаётся handle (in/out), для внешнего объекта — его порт (out→in, проверка
  напряжений); если у внешнего объекта порта нет, он создаётся `ports/ensure` в момент связи.

### 3.2. Связь «внешний блок → ячейка» (07)

Сценарий: два блока БКРУ (A — с ресайзом/ячейками этапа 3, B — новый). Тянем линию от
`l-out` блока B к `cell:<id>:in` ячейки №1 блока A:

* `POST /api/assets/<cellId>/ports/ensure` → 200 (у ячейки появляются IN-1/OUT-1);
* `POST /api/links` → **201** с `from_port_id` порта блока B и `to_port_id` **порта ячейки** A;
* статус в UI: «Связь создана (порт ячейки): UI3-B БКРУ … → Яч. №1 (Вводная)»;
* в БД: `BKRU-200:OUT-1 → CELL-315:IN-1`, у порта `parent_asset_id = <блок A>` (§6);
* на холсте линия приходит ровно в кружок ячейки (07), а не в край блока.

### 3.3. Соединение блоков целиком (08)

Отдельно проверено, что старое поведение не сломано: линия от `r-out` блока A к `l-in`
блока B открывает прежний диалог «Новая связь» → «Соединить» → `POST /api/links` 201,
`BKRU-199:OUT-1 → BKRU-200:IN-1` (порты самих блоков, §6).

## 4. Перетаскивание ячеек внутри блока

### 4.1. Drag handle и extent

* У каждой ячейки в режиме редактирования — ручка `⠿` (`data-testid="cell-drag-<cellId>"`,
  классы `nodrag touch-none`), спозиционирована абсолютно в правом нижнем углу, чтобы не
  отнимать ширину у подписи. Перетаскивание — pointer events с `setPointerCapture`.
* Позиции хранятся в координатах контента блока; ограничение «по рамкам родителя» —
  `clampCellBox` (`x ∈ [0, bodyW−cellW]`, `y ∈ [0, bodyH−cellH]`), т.е. ячейка физически
  не может выйти за тело блока; отрицательные координаты тоже запрещены.
* Во время drag ячейка получает `z-[6] ring-accent` (видно, что тащим), соседние не дёргаются.

### 4.2. Сохранение

По `pointerup` вызывается `onCellDragEnd` → в pending попадает блок; через 2 с уходит
`PUT /api/topology/layout` c `{asset_id: cellId, local_x, local_y}` (и размером блока).
Сохранение проверено 04: `left=186, top=66` (было `160, 22`), ячейка внутри `body 476×200`.

### 4.3. Восстановление после перезагрузки

05: после полной перезагрузки и возврата в режим редактирования ячейка снова на
`left=186, top=66`; блок имеет `data-block-layout="freeform"` и `schema_width=500`.
Правило показа: свободная раскладка включается, если у блока есть `schema_width/height`
и все ячейки имеют `local_x/local_y` в рамках блока; иначе — привычная сетка. Это защищает
старые импорты (координаты composite-ячеек 60…660 px в блок 320 px) от «рассыпания».

## 5. Автосейв и индикация

### 5.1. Автосейв без кнопки

`flushSave` — единая точка: и кнопка «Сохранить раскладку» (ручной триггер), и автосейв.
После отпускания узла / ресайза / перетаскивания ячейки ставится debounce **2000 мс**
(`AUTOSAVE_DEBOUNCE_MS`), затем уходит `PUT /api/topology/layout` **только с изменённым**:
перемещённые узлы (`x/y`), блоки (`width/height`) и ячейки затронутых блоков
(`local_x/local_y`). Payload режется на пачки по 200 (`LAYOUT_CHUNK_SIZE`, лимит backend 500),
поэтому даже «Авто-раскладка» на 90+ узлах уходит несколькими запросами.
Ручная кнопка осталась (ручной триггер + порты).

MutationObserver на плашке зафиксировал последовательность (02/04):
`pending «Изменения не сохранены — сохраню автоматически»` → `saving «Сохранение…»`
(спиннер `.schema-spinner`) → `saved «Все изменения сохранены ✓»` (зелёная).

### 5.2. Механика

* `pendingRef` — наборы изменённых узлов/блоков; при успехе удаляются только сохранённые
  id (изменения, пришедшие во время запроса, не теряются и досылаются).
* `savedBlockSizesRef`/`blockCellsRef`/`cellOverridesRef` — свежие размеры и раскладка
  до ответа сервера (чтобы промежуточный reload графа не откатил размер).
* Индикатор — `data-testid="schema-autosave"` c `data-phase` (`pending|saving|saved|error`),
  `role=status/alert`, `aria-live`; тексты и тон — из `saveIndicator()` (`lib/schemaStage3.ts`).

### 5.3. Ошибка и повтор

09: сеть отключена (`Network.emulateNetworkConditions offline`), ячейку подвинули →
через 2 с запрос падает → красная плашка **«Ошибка сохранения, проверьте сеть»** + кнопка
«Повторить»; автоматический повтор запланирован через **5000 мс** (`AUTOSAVE_RETRY_MS`).
10: после включения сети повтор прошёл → индикатор снова зелёный «Все изменения сохранены ✓»,
ядро раскладки сохранилось. Во время всего прогона **0 console errors, 0 API-ошибок**
(кроме ожидаемого offline-запроса).

## 10. Ограничения и замечания

* **Ресайз перекладывает ячейки по сетке**: ручные позиции ячеек сбрасываются при ресайзе
  (иначе контент оставался бы узким столбцом слева). Это осознанное поведение: сначала
  задают размер, затем расставляют ячейки. После перезагрузки восстанавливаются
  последние сохранённые `local_x/local_y`.
* Свободная раскладка (абсолютные ячейки) включается для блока, у которого есть
  `schema_width/height` **и все** ячейки имеют `local_x/local_y` в рамках блока; иначе —
  сетка. Legacy composite-координаты (60…660 px в блок 320 px) поэтому не «рассыпают» блок.
* `PUT /api/topology/layout` и `POST /api/assets/{id}/ports/ensure` — админские на backend
  (t1/текущий контракт). У пользователя с `settings.edit`, но без роли admin, автосейв
  покажет красную плашку «Ошибка сохранения…» (403), а связь через порт ячейки — сообщение
  об ошибке прав. Это ограничение backend, в рамках этапа 3 не менялось.
* Связь ячейка↔ячейка **внутри одного блока** на холсте не рисуется (это петля блока;
  такие связи, как и раньше, показываются перемычками/карточкой). Связи ячеек с внешними
  объектами и между разными блоками рисуются — через handle ячейки.
* `buildEdges` теперь пропускает jumper-связи и связи с несуществующими (свёрнутыми) узлами:
  это убирает предупреждения React Flow о ненайденном узле (раньше они попадали в консоль
  при кабельных связях от ячеек).
