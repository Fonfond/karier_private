## 1. Итог

Перенос оборудования/ячеек между контейнерами реализован как **атомарная серверная операция** с предварительными проверками и явным подтверждением при риске разрыва связей:

- **Backend:** новый endpoint `POST /api/schema/assets/{asset_id}/relocate` (`app/api/routers/schema_blocks.py`) + сервис `relocate()` (`app/services/schema_blocks.py`). Меняются только `parent_asset_id` / `schema_block_id` / локальные координаты; **порты и связи не трогаются**, поэтому существующие линии остаются валидными. Все проверки — до мутаций, запись — одной транзакцией (`flush` + `commit`, `rollback` при ошибке).
- **Проверки без изменения данных:** нельзя перенести в не-контейнер, в себя, в своего потомка; контейнеры не переносятся; структурные элементы (шина/ввод/ТТ/ОПН) защищены; проверяются напряжение, роль/направление и границы карты (для возврата на схему).
- **Подтверждение:** если перенос ломает отображение перемычек, оставляет связи между контейнерами или меняет линию/фидер, сервер отвечает `409 schema.move.confirmation_required` со списком причин (`fields.reason_1…N`), а фронтенд показывает `ConfirmDialog` с объяснением. Отмена — данные не меняются (сервер ещё ничего не записал).
- **Frontend:** перенос через контекстное меню узла («⇄ Перенести в блок/контур…») и через кнопку `⇄` у ячейки внутри блока (в режиме редактирования); диалог со списком блоков/контуров и пунктом «Без контейнера — вернуть на схему». Ошибки (напряжение/направление/границы) показываются в диалоге понятным текстом.
- **Undo/redo:** перенос целиком обёрнут в `pushCommand`: undo возвращает старый контейнер (и старые локальные координаты/позицию), redo повторяет перенос; реестр не дублируется (операция — только `UPDATE`).
- **S-8 (фидеры):** если у объекта и у целевого контейнера есть линии (`links.line_id`) и они разные — предупреждение «Смена линии/фидера: …».

Проверки: backend поднабор — **12 passed** (5 новых тестов), frontend — typecheck exit 0, build exit 0 (509 модулей), vitest 20 passed.

## 3. Backend

### 3.1 Endpoint (`app/api/routers/schema_blocks.py`)

`POST /api/schema/assets/{asset_id}/relocate` (require_admin), тело:

```json
{ "target_asset_id": "uuid|null", "confirm": false, "x": 0, "y": 0, "local_x": 0, "local_y": 0 }
```

Ответ `RelocateOut`: `asset` (AssetOut), `warnings: string[]`, `old_parent_id`, `old_block_id`, `old_local_x/y`, `old_schema_x/y` — достаточно, чтобы фронтенд сделал точный undo.

### 3.2 Сервис (`app/services/schema_blocks.py`, `relocate()`)

Порядок проверок (до любых изменений):

1. target не сам объект (`schema.move.self`), существует, тот же pit; является блоком/контуром (`is_container`), иначе `schema.move.not_container`.
2. Нет цикла: target не потомок переносимого объекта (`_would_cycle` по `parent_asset_id`).
3. Контейнеры не переносятся (`schema.move.container`) — переносятся ячейки/оборудование.
4. Возврат на схему (`target=null`) требует `x,y` и проходит `gis.check_bounds` (`schema.move.position_required` / `asset.out_of_bounds`).
5. Структурные роли (`STRUCTURAL_ROLES`) защищены (`schema.move.structural_protected`).
6. Напряжение: если у объекта однозначное напряжение, а у контейнера (порты + дети) — другое → `schema.move.voltage_mismatch` с текстом «…6 кВ не совпадает с … 35 кВ».
7. Направление/роль: для библиотечных блоков роль `input/outgoing/section` должна входить в роли шаблона (`schema.move.direction_conflict`).
8. Причины подтверждения (`_move_reasons`): перемычки с ячейками прежнего блока (перестанут отображаться), обычные связи с объектами прежнего контейнера (останутся межконтейнерными), смена линии/фидера по `links.line_id`. Если причины есть и `confirm=false` → `409 schema.move.confirmation_required`, `detail` со списком, `fields.reason_1…` + `requires_confirm=true`.
9. Мутация: для контейнера — `parent_asset_id=target.id`, `schema_block_id=target.id`, локальные координаты (переданные или следующий слот `max(local_x)+120`); для схемы — очистка контейнера и `schema_x/y`. `version += 1`, один `commit`; ошибка — `rollback`. Аудит `schema.asset_relocated` с from/to и списком предупреждений.

Порты и связи не изменяются — это и обеспечивает их валидность после переноса.

**Ограничения:**
- **Браузерный E2E не выполнялся** (dev-сервер в этом цикле не поднимал): фронтенд проверен типизацией/сборкой и разбором обработчиков; API-сценарии покрыты pytest.
- **Undo/redo фронтенда** — UI-логика (pushCommand + повторный relocate), отдельных браузерных тестов нет; серверные операции, которые она вызывает, покрыты API-тестами (включая возврат в старый контейнер через `old_block_id` и точные `local_x/y`).
- **«Разрыв связи»** трактуется как потеря отображения перемычек в блоке и появление межконтейнерных связей; сами связи/порты не разрываются (данные сохраняются). Так безопаснее и соответствует «связи и порты остаются валидными».
- **Напряжение** проверяется только когда у обеих сторон однозначное напряжение (трансформаторы 35/6 и смешанные контейнеры пропускаются — иначе ложные отказы).
- **Направление** ограничено ролями `input/outgoing/section` и шаблонами библиотечных блоков; контуры не ограничиваются.
- **Фидеры** определяются по `links.line_id`; если линия не назначена, предупреждения не будет.
- **Redo** восстанавливает контейнер и связи, но свободный слот в новом контейнере вычисляется сервером заново (точная позиция слота при redo не гарантируется); дублей в реестре нет — операция только обновляет объект.
- Контейнеры (блоки/контуры) по-прежнему не переносятся между собой — при необходимости это отдельная задача (нужна перестройка вложенных `schema_block_id`).
