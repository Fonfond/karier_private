## 10. Оговорки и ограничения

1. **Выбор блока в drawer на мобильном может не поставить блок**, если центр текущего
   вьюпорта лежит вне карты: legacy `POST /api/schema/blocks/{code}/instantiate` валидирует `x/y`
   по границам карты (0…1024 × 0…576 м), а в demo-схеме центр вьюпорта оказался `1280,-140` →
   **422 `asset.out_of_bounds`**, показанный тостом (drawer при этом закрывается — требование
   приёмки выполнено). Это существующее поведение старого эндпоинта/демо-данных, не изменение 38a;
   установка через «▤ По шаблону» на мобильном работает штатно (проверки 32–40).
2. **Сжатие блока ниже содержимого** (ширина 320→180 при 6 ячейках) приводит к reflow-позициям
   ниже новой высоты, и автосейв штатно возвращает **422 `layout.out_of_bounds`** — существующее
   ограничение этапа 3 (описано в 35b §6.3/§10), не связанное с 38a. Приёмочный сценарий
   проверяет обычный ресайз (увеличение 320→440), он сохраняется без ошибок; наблюдение
   сохранено в `observation-shrink-422.png`.
3. **Тост при очень длинном тексте занимает 2 строки** (374×47 px) — остаётся компактным,
   не сдвигает вёрстку и не блокирует жесты (`pointer-events:none`).
4. На мобильном «До» кадр `100-mobile-before.png` снят с DPR 3 (1170×2532) в момент тура;
   для честного сравнения 390×844 воспроизведён отдельный `before-01-schema-mobile.png` без тура
   на том же demo-стенде.
5. Demo-стенд `karier_db` в Docker получил только временный блок `QA38B-БКРУ-*` (создан для
