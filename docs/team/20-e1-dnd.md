## 1. Итог

Блоки из «Библиотеки блоков» теперь можно перетаскивать на схему:

- **Drop в точке сброса**: координаты считаются через `screenToFlowPosition({ x: clientX, y: clientY })` и передаются в существующий `gisApi.instantiateBlock(code, x, y)` — один вызов API = один блок в реестре (корень + ячейки создаются на бэкенде, как и раньше).
- **История**: создание обёрнуто в `pushCommand('установка блока', undo, redo)` — `undo` удаляет корень и все ячейки, `redo` возвращает их (прежняя логика, теперь работает и для drop).
- **Камера подводится** к новому блоку через существующий `focusAsset(rootId)` (два прохода `fitView` после ответа API и после перерисовки графа).
- **Подсветка зон**: пока карточку тянут, канвас обводится акцентом и показывает подсказку «Отпустите — “…” встанет здесь»; над панелями/тулбаром — красная рамка и «Недопустимая зона — перетащите … на поле схемы». Пока курсор нигде не на канвасе — нейтральная подсказка «Перетащите … на поле схемы».
- **Клик без перетаскивания сохранён**: клик по карточке ставит блок в центр видимой области схемы (раньше — в фиксированную точку 120,140; теперь это именно «центр», как в приёмке).
- Двойной drop/повторный вызов защищён `placingBlockRef` (пока идёт создание, второй drop игнорируется).

Изменён только `SchemaView.tsx`. `AddToSchemaPanel.tsx` и `gis.ts` в inScope просмотрены — изменений не потребовалось: `instantiateBlock(code, x, y)` уже принимает координаты, панель добавления остаётся модальной и работает через клик (drag из-под модалки на канвас невозможен без её закрытия — вне рамок E-1).

**Ручная проверка (QA, на поднятом стенде):**
1. Войти администратором (`settings.edit`) → Карта → «Схема». В «Библиотеке блоков» (слева) навести на карточку — курсор `grab`.
2. Начать перетаскивание: сразу появляется нейтральная подсказка с названием блока; при входе на канвас — акцентная рамка и «Отпустите — блок встанет здесь»; при уходе на тулбар/панель — красная рамка и «Недопустимая зона…». Отпускание над тулбаром не создаёт блок (сообщение «Блок не добавлен»).
3. Отпустить на канвасе: блок появляется **в точке сброса** (сравнить с видимой областью; при уменьшенном масштабе — с учётом зума), камера подъезжает к нему (`fitView`), в реестре — один новый объект (блок + ячейки), без дублей.
4. Нажать «Отменить» (↩) — блок и его ячейки исчезают; «Повторить» (↪) — возвращаются.
5. Кликнуть карточку без перетаскивания — блок ставится в центр видимой области (как раньше клик работал, но теперь именно в центр).
6. Проверить под не-админом: библиотека не отображается, перетаскивание невозможно.
7. Проверить, что drag/drop не мешает обычному выделению/перетаскиванию узлов и работе тулбара.

## 5. Ограничения

- **Браузерный E2E не выполнялся** (dev-сервер в этом цикле не поднимался): реализация проверена сборкой, типизацией и разбором обработчиков; HTML5 drag-события в браузере стандартные, но фактический UX (рамка/подсказка, точка сброса) стоит подтвердить по шагам §4.
- **HTML5 drag&drop не работает на тач-устройствах** (планшеты): там остаётся клик по карточке (центр). Pointer-based DnD для тача — отдельная задача, если понадобится.
- **Auto-scroll канваса при перетаскивании к краю** не реализован: React Flow сам не панорамирует при HTML5 drag; для больших схем можно добавить позже.
- **Drop во время незавершённого создания** игнорируется (`placingBlockRef`) — это осознанная защита от дублей.
- Кастомный MIME `application/x-karier-block` дублируется `text/plain`; при drop код берётся из `dataTransfer`, а при его отсутствии — из состояния `dragBlock` (fallback для браузеров, не отдающих кастомный тип).
- `AddToSchemaPanel.tsx` и `gis.ts` в inScope не менялись: `instantiateBlock` уже поддерживает `(code, x, y)`, панель — модальная и использует клик; её карточки не являются «библиотекой блоков» из приёмки.
