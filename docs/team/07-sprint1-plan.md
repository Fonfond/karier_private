## 10. Ограничения и риски

- S-1: установка Git может требовать прав администратора; создание приватного репозитория и push — действие владельца, если нет авторизованного `gh`.
- S-1: ротация пароля затрагивает тестовую БД (та же роль) — `TEST_DATABASE_URL` обновляется вместе с `.env`; при сбое откат на прежний пароль и повтор.
- S-5: ручная выдача OTP меняет процесс регистрации на стенде — инструкция для админа обязательна (F-3).
- S-8: второй карьер — только разделение по фидеру, без пересмотра модели прав; тяжёлые миграции не делаем.
- E-2: перестановка между контурами меняет `schema_block_id`/`parent_id` — обязательны тесты на целостность связей.
- F-1: Docker на Windows-хосте проверяется локально через Docker Desktop; целевой сервер — Linux (amd64), образы без привязки к ОС.
