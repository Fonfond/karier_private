## 1. Итог

Три причины «тяжёлого» редактора схемы устранены:

1. **`AssetNode` мемоизирован** через `React.memo` с явным компаратором пропсов (`areNodePropsEqual`): узел перерисовывается только при изменении своего `selected`, данных объекта/блока, флагов режимов или обработчиков. Смена выделения теперь перерисовывает 1–2 узла вместо всех 250+.
2. **Полная пересборка узлов и связей выполняется только при смене `graph`.** Флаги режимов и `selectedId` больше не входят в зависимости эффекта пересборки: они применяются точечными функциями `applyNodeModes` / `applySelection`, которые возвращают исходный массив, если ничего не изменилось, и создают новые объекты только для реально изменённых узлов. Обработчики и текущие флаги читаются из «последних» ref-ов, поэтому нестабильные колбэки `MapPage` (`onSelect`, `onGraphChanged` — новые на каждый рендер) больше не триггерят rebuild.
3. **dagre запускается только при наличии узлов без `schema_x`/`schema_y`, и раскладывает только их.** Если у всех узлов координаты сохранены — раскладки нет вообще; если без координат один узел — dagre раскладывает один узел, а не все 250.

Замеры на синтетической схеме **250 узлов / 300 связей** (медианы, Node 26): полная пересборка с dagre **≈102–107 мс → 0,01 мс** для смены режима/выделения; `nodePositions` при сохранённых координатах **102,60 мс → 0,01 мс**.

Проверки: typecheck exit 0, build exit 0 (509 модулей, 4,84 с), vitest 20 passed, headless-бенчмарк/ассерты — 4/4 PASS + 2 INFO.

## 3. Замеры до/после

Стенд: Node.js 26.13.1, Windows, десктоп; синтетическая схема **250 узлов, 300 связей**; медиана из 7 прогонов для dagre-операций и 101 прогона для лёгких обновлений (после 2 прогревочных). «До» — воспроизведение прежнего поведения по коду (dagre для всех узлов; rebuild при каждом изменении deps; полный `map` с новым `data`/`onPortMove` при смене режима/выделения).

| Сценарий | До | После | Комментарий |
|---|---:|---:|---|
| `nodePositions`: **все 250 узлов с координатами** | **102,60 мс** | **0,01 мс** | dagre не запускается (было — полная раскладка, результат которой игнорировался) |
| `nodePositions`: **1 узел без координат** из 250 | **99,47 мс** | **0,24 мс** | dagre раскладывает 1 узел, а не 250 |
| `nodePositions`: **все без координат** | 108,29 мс | 108,29 мс | dagre объективно нужен — деградации нет |
| Переключение режима (`editable`/`draggable`): полный rebuild vs `applyNodeModes` | **106,81 мс** | **0,01 мс** | ушли dagre + `buildEdges` + пересоздание замыканий `onPortMove` |
| Выделение узла: rebuild-путь vs `applySelection` | **106,81 мс** | **0,00 мс** | JS-время; главное — перерисовка **1–2 узлов вместо 250** |
| `buildEdges` (300 связей) | 0,12 мс | 0,12 мс | сам по себе дешёвый, но теперь не вызывается на флаги/выделение |
| Новых объектов `data` при выделении | 250 | **1–2** | прокси для числа ре-рендеров узлов (см. §4) |

Ассерты бенчмарка (все прошли):
- идентичные props → `areNodePropsEqual` = `true` (узел не рендерится); смена `selected` / `editable` / `onPortMove` → `false`;
- `applySelection(nodes, null)` и `applyNodeModes(nodes, flagsOff)` возвращают **тот же массив**;
- первое выделение меняет 1 узел, перенос выделения — 2; повторное с тем же id — 0;
- сохранённые координаты (`node-5`: x=1300, y=0) остаются нетронутыми; узлу без координат позиция назначается.

## 4. Методика и ограничения замеров

- **React Profiler в браузере не запускался**: в этом цикле не поднимался dev-сервер/браузер (правки только в исходниках; сборка проверяется отдельно). Вместо этого:
  - замеры `performance.now()` на **чистых функциях** модуля (`nodePositions`, `dagrePositions`, `buildEdges`, `applyNodeModes`, `applySelection`), выделенных в экспортируемые функции — это тот же код, что исполняется в эффектах;
  - число перерисовываемых узлов оценивается по числу новых объектов `node`/`data` (при стабильных ссылках React Flow + `memo` не рендерят узел). Это консервативная оценка: реальный выигрыш не меньше, т.к. каждый узел — десятки DOM-элементов и `getBoundingClientRect` в `useLayoutEffect`.
- Модуль для бенчмарка собирался esbuild'ом с заглушкой `@xyflow/react` (`.tmp/xyflow-stub.mjs`, вне git); бандл — `.tmp/e3-bundle/SchemaView.mjs`, запуск — `.tmp/e3-harness.mjs`. Артефакты в `.tmp/` не коммитятся.
- Числа — порядок величины на десктопе; на планшете абсолютные значения dagre будут выше, соотношение — тем же. Для финального «браузерного» подтверждения — шаги в §6.
- **Смешанная схема** (часть узлов с координатами, часть без): dagre раскладывает только узлы без координат, не учитывая позиции сохранённых. Для типичного случая «все сохранены» или «все новые» это неважно; если появится много частично размещённых схем — можно добавить укладку относительно сохранённых соседей (отдельная задача, вне E-3).
