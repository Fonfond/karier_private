## 2. Что сделано

### 2.1 Поток создания в реестре

`Реестр оборудования` → `+ Объект` открывает модалку «Новый объект». Сверху — вкладки классов,
под ними — селект «Модель (тип)» с типами только выбранного класса, затем основные поля
(название, код, состояние, родитель, расположение, X/Y) и секция «Паспорт оборудования» —
динамические поля выбранного типа.

* при открытии модалки выбирается первый непустой класс (или класс последнего выбранного типа);
  «Отмена» не сбрасывает выбранный тип — как и раньше;
* смена вкладки класса переключает тип на первый в этом классе;
* смена типа пересобирает поля паспорта и подставляет `default_value`
  (например, «Состояние кабеля» → `installed`);
* типы загружаются один раз вместе с реестром: `GET /api/asset-types?with_fields=1`
  (`gisApi.types({ with_fields: true })`).

### 2.2 Группы классов (вкладки)

Источник — `equipment_class` (миграция 0015), fallback — `group_code`, затем старая `category`
(совместимость со старым API). Порядок вкладок фиксирован:

| `equipment_class` | Вкладка (UI) | Типы в тестовой БД (живой API, §4.1) |
|---|---|---|
| `distribution` | 🏭 Распредустройства | `substation`, `bus_section`, `bkru` |
| `transformer_assembly` | ⚡ Трансформаторы и сборки | `ksr`, `yaku_1t`, `ktp` |
| `switching` | 🔌 Коммутационные | `yaku` |
| `cell` | 🔲 Ячейки | `cell` |
| `cable` | 🧵 Кабели | `cable` |
| `mobile` | 🚜 Мобильное | `dmo`, `dmp`, `bmp`, `gen_diesel`, `gen_petrol`, `ekg`, `cuckoo`, `mast`, `pump` |
| `line` | 🗼 Опоры | `pole` |
| `source` | 🔋 Источники | — (появится с типом класса `source`) |
| `equipment` | 📦 Прочее | запасная вкладка для типов без класса |

Дополнительно сгруппированы (optgroup) фильтр «Тип» в тулбаре реестра и селект типа при
«Собрать в группу» — плоских списков типов в реестре не осталось.

### 2.3 Поля паспорта: контрол по `data_type`

`typeFields(type)` берёт `fields` из ответа с `with_fields=1` (сортировка по `sort_order`),
а если поля не пришли (старый backend/пустая таблица) — выводит их из `attr_schema`/`required_attrs`
тем же порядком, что мигратор 0015 (обязательные первыми, дальше по алфавиту).

| `data_type` | Контрол |
|---|---|
| `number` | текстовый input, `inputMode=decimal`, принимает «1250,5»; единица справа внутри поля |
| `integer` | текстовый input, `inputMode=numeric`, проверка целого |
| `text` | текстовый input |
| `boolean` | select `— не задано — / да / нет` |
| `date` | `input type="date"` (ГГГГ-ММ-ДД) |
| `select` | select с опциями; известные значения переведены (`installed` → «на оборудовании», `reserve` → «в запасе», `repair` → «в ремонте»); пустой список опций → текстовый input (backend допускает любое значение) |

Обязательные помечены `*` (`title="Обязательное поле"`, `aria-required`), единица — рядом с
подписью (`Длина, м`, `Мощность, кВт`) и внутри числового поля. Поля сгруппированы по
`group_label` (`Кабель`, `Напряжение`, `Мощность`…). У типа без полей — подсказка
«У этого типа нет полей паспорта: админ задаёт их в разделе «Типы объектов»».

### 2.4 Клиентская проверка и сборка `attrs`

`validateAssetFields` до сети проверяет: обязательность, число/целое, да/нет, дату,
принадлежность списку, `min`/`max`. Сообщения совпадают с backend:
«Обязательное поле», «Ожидается число», «Ожидается целое число», «Ожидается да/нет»,
«Ожидается дата в формате ГГГГ-ММ-ДД», «Недопустимое значение (допустимо: …)»,
«Значение меньше/больше минимального/максимального (N)».

При ошибке модалка не закрывается, под каждым полем сообщение и `aria-invalid`, сверху —
сводка «Заполните обязательные поля: Марка кабеля, Длина».

`buildAttrs` собирает `attrs` для `POST /api/assets`: `number` → `Number` (запятая → точка),
`integer` → целое, `boolean` → `true/false`, `text`/`date`/`select` → строка; пустые значения
не отправляются. Отдельно: значение поля `lifecycle_status` дополнительно уходит в колонку
`gis.assets.lifecycle_status` (0015) — чтобы «в запасе» в форме не расходилось с колонкой
(backend иначе ставит `installed`).

### 2.5 Серверный 422: `fields` + `field_labels` под полями

`lib/api.ts`: `ApiError` теперь сохраняет `fieldLabels` из problem+json (раньше `field_labels`
терялись, и клиент мог показать только общий текст).

`mapServerFieldErrors(fields, err.fields, err.fieldLabels)` раскладывает ключи:
* код поля паспорта (`cable_mark`) или путь (`attrs.cable_mark`) → сообщение под этим полем,
  подпись из `field_labels`, иначе из описания поля типа, иначе из словаря формы;
* основные поля (`name`, `type_code`, `code`, `status`, `x`, `y`, `parent_id`, `location_text`) →
  под соответствующим input;
* незнакомый ключ не теряется — попадает в сводку (`Warranty until: Ожидается дата`), а не
  молча игнорируется.

Сводка строится по распознанным полям: «Проверьте: поля паспорта — Марка кабеля, Длина» —
то есть даже без `detail` понятно, что и где исправлять. Ошибка не закрывает модалку и не
сбрасывает введённые значения.

### 2.6 Сохранённые сценарии

* название (2…255, обязательное), код (необязательный, верхний регистр, авто-генерация),
  состояние (`on/off/standby/maintenance/decommissioned`), расположение текстом,
  X/Y (взаимная обязательность, числа, границы карты) — без изменений;
* «Родительский объект»: в форме его не было, добавлен необязательный селект
  (те же `parents`, что в фильтре: source/equipment без ячеек) → `parent_id` в payload;
* после создания — прежние сообщения про «Не размещённые» и размещение на карте;
* ошибки создания показываются только в модалке (`formError`), страничный `error`
  остаётся для загрузки/удаления, форма не «прыгает».

```json

 "fields":[
  {"code":"cable_mark","label":"Марка кабеля","unit":null,"data_type":"text","required":true,"group_label":"Кабель","sort_order":10},
  {"code":"length_m","label":"Длина","unit":"м","data_type":"number","required":true,"group_label":"Кабель","sort_order":20},

  {"code":"section_mm2","label":"Сечение","unit":"мм²","data_type":"number","group_label":"Кабель","sort_order":40},
  {"code":"voltage_kv","label":"Напряжение","unit":"кВ","data_type":"number","group_label":"Напряжение","sort_order":50}]}
```

`ktp` — 3 поля (`power_kva`, `voltage_in_kv`, `voltage_out_kv`), `dmo`/`dmp`/`bmp` — `power_kw`

### 4.2 `POST /api/assets`: 422 → 201

```text
POST /api/assets {"name":"Проверка формы — кабель","type_code":"cable","status":"off"}
→ 422 {"title":"Проверьте поля объекта: Марка кабеля, Длина","code":"validation.failed",
       "fields":{"cable_mark":"Обязательное поле","length_m":"Обязательное поле"},
       "field_labels":{"cable_mark":"Марка кабеля","length_m":"Длина"}}

POST /api/assets {..., "attrs":{"cable_mark":"ВВГ","length_m":"много"}}
→ 422 {"fields":{"length_m":"Ожидается число"},"field_labels":{"length_m":"Длина"}}

POST /api/assets {..., "attrs":{"cable_mark":"ВВГ 3×2,5","length_m":305.5,"section_mm2":2.5,
                               "lifecycle_status":"reserve"},"lifecycle_status":"reserve"}
→ 201 {"code":"CABLE-3","attrs":{"length_m":305.5,"cable_mark":"ВВГ 3×2,5","section_mm2":2.5,
        "lifecycle_status":"reserve"},"lifecycle_status":"reserve"}

DELETE /api/assets/{id} → 200 {"message":"Объект удалён"}
```

Первый 422 — ровно тот случай, который раньше выглядел как «Проверьте атрибуты объекта»:
теперь UI не отправляет такую форму (клиентская проверка), а если сервер всё же ответил 422 —
`fields`/`field_labels` раскладываются под поля («Марка кабеля: Обязательное поле»,
«Длина: Обязательное поле»). Полезная нагрузка `201` совпадает с тем, что собирает `buildAttrs`
и `cableLifecycleStatus` в форме.

  (БКРУ-6, ПС 17/секция) — этап 2; UI уже отправляет выбранное «Состояние кабеля» и в `attrs`,
  и в колонку.

## 7. Как проверить руками

1. `cd C:\karier\karier\src-v2; npm run dev` (backend на `127.0.0.1:8001`); вход админом.
2. `Реестр оборудования` → `+ Объект`: видны вкладки классов, пустых вкладок нет.
3. Вкладка «Трансформаторы и сборки» → модель «КТП»: появились поля «Полная мощность, кВ·А»,
   «Напряжение на входе, кВ», «Напряжение на выходе, кВ».
4. Вкладка «Мобильное» → «ДМО»: поле «Мощность, кВт» помечено `*`; нажать «Создать объект»
   без него — форма не отправит запрос и подсветит поле «Обязательное поле».
5. Вкладка «Кабели»: заполнить «Марка кабеля» и «Длина», выбрать «в запасе» — объект создастся,
   в карточке `attrs` содержит значения, а состояние кабеля — «в запасе».
6. Отправить заведомо неверное число (например, «много») — сервер ответит 422, сообщение
   появится под полем «Длина», модалка останется открытой.
