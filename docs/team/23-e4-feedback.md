## 1. Итог: что теперь видит пользователь

| Ситуация | Обратная связь |
|---|---|
| Тянет блок из библиотеки над полем схемы | зелёная/акцентная рамка + подсказка «Отпустите — “…” встанет здесь, камера наведётся» (сама скрывается через 6 с) |
| Тянет блок над тулбаром/панелью | **пульсирующая красная рамка (schema-danger)** + причина: «Недопустимая зона: “…” встаёт только на поле схемы, не на панели и не на тулбар» |
| Перенос объекта/ячейки в неподходящий контейнер | в диалоге — **красный блок причины** с ⚠ и текстом: напряжение, направление/роль, границы, фидер/линия, protected, self/cycle и т.д.; та же причина всплывает над канвасом (7 с) |
| Перенос изменит связи | ConfirmDialog со списком причин (было в E-2), после подтверждения — «перенесён, камера наведена» |
| Блок создан / объект перенесён | статус-строка: «Блок «…» установлен на схему, ячеек: N — камера наведена» / ««…» перенесён в новый контейнер — камера наведена», `focusAsset` подводит камеру; статус скрывается через 8 с |
| Открыта легенда | три блока: **Питание** (красный — под напряжением, зелёный — отключено), **Связи** (сплошная/пунктир/точки-перемычка/стрелка направления/внутренняя), **Фидеры и линии** + список обозначений ГОСТ с количеством |

## 2. Что изменено

### 2.1. `src/components/map/SchemaView.tsx`

1. **Классификатор причин отказа переноса** (`RELOCATE_DANGER` + `export function relocateDangerText(err)`,
   ~:735-755): коды API E-2 → короткая фраза для подсветки:
   `schema.move.voltage_mismatch` → «напряжения объектов не совпадают»,
   `direction_conflict` → «роль/направление не совпадает с шаблоном блока»,
   `asset.out_of_bounds` → «точка за границами схемы»,
   `confirmation_required` → «перенос изменит связи — нужно подтверждение»,
   `structural_protected`, `schema.move.self|not_container|cycle|container` — покрыты;
   неизвестный код → «Перенос отклонён: <текст сервера>» (в т.ч. любые фидерные/линейные отказы).
2. **Состояния обратной связи** (`dangerHint`, `showDragHint`, `relocateDanger`, ~:884, :1313) и
   **три эффекта с таймаутами** (~:1165-1182): статус 8 с, опасность 7 с, drag-подсказка 6 с
   (сбрасывается на каждый новый drag). Подсказки — `pointer-events-none`, поэтому не перехватывают
   клики и не перекрывают кнопки.
3. **Опасность при переносе** (~:1405-1416): в `performRelocate` при ошибке заполняются
   `relocateDanger` + `dangerHint`, причина показывается и в диалоге, и над канвасом; сбрасывается при
   открытии диалога и после успешного переноса.
4. **Подсветка недопустимой зоны drag&drop** (~:2420-2450): красная пульсация `schema-danger`,
   текст причины, подсказка скрывается по таймауту (рамка остаётся, пока идёт drag).
5. **Статусы после действий** (~:1218, ~:1385-1390): текст с названием и числом ячеек + «камера
   наведена»; `focusAsset(...)` вызывается сразу после `setStatus`, т.е. камера подводится к элементу.
6. **Легенда редактора** (~:2660-2710): статические блоки «Питание» (цвета из `POWER_COLOR`:
   `#F04438` — под напряжением, `#22C55E` — отключено), «Связи» (сплошная — соединена/под напряжением,
   пунктир — разомкнута, точки — перемычка, стрелка — направление «выход → вход», тонкая — внутренняя),
   «Фидеры и линии» (фидер — линия от источника; красная/зелёная окраска), ниже — прежний список
   обозначений ГОСТ с количеством. Панель открывается даже при пустом списке символов.
7. **Оверлей опасности над канвасом** (~:2454-2462): `role="alert"`, `aria-live="assertive"`,
   позиция `top-14` по центру (ниже тулбара, выше полотна), `pointer-events-none`.

## 4. Ручная проверка (для QA, 7 шагов)

1. Открыть карту → «Схема» → включить «Редактировать» (нужны права admin/editor).
2. Из библиотеки блоков потянуть карточку на полотно: должна появиться акцентная рамка и подсказка
   «Отпустите…»; подсказка исчезает через ~6 с, если продолжать держать.
3. Провести карточку над тулбаром/левой панелью: рамка краснеет и пульсирует, в подсказке — причина
   «Недопустимая зона…»; отпустить там — блок не создаётся, в статусе «Блок не добавлен…».
4. Отпустить на полотне: блок создаётся, камера подводится к нему, статус «Блок «…» установлен на
   схему, ячеек: N — камера наведена» (исчезает через 8 с).
5. Контекстное меню узла → «⇄ Перенести в блок/контур…» → выбрать контейнер с другим напряжением:
   в диалоге появляется красный блок «⚠ Нельзя: напряжения объектов не совпадают» и текст сервера;
   над канвасом — та же причина. Для контейнера, меняющего линию/перемычки, — подтверждение со списком.
6. Успешный перенос: статус ««…» перенесён … — камера наведена», камера подводится.
7. «Легенда»: проверить разделы «Питание» (красный/зелёный), «Связи» (сплошная/пунктир/точки/стрелка),
   «Фидеры и линии»; на карте — тот же смысл в правом нижнем блоке «Обозначения».

## 5. Ограничения

1. **Браузерный прогон не выполнялся** (dev-сервер не поднимался, чтобы не мешать приёмке): проверены
   типизация, сборка, юнит-тесты и логика классификатора причин; визуальные шаги §4 — для QA.
2. **Тайминги подсказок** (6/7/8 с) выбраны эвристически, вынесены в константы внутри эффектов;
   при жалобах на назойливость/быстроту меняются в одном месте.
3. **Причины фидерных отказов** приходят с бэка как `direction_conflict` / `confirmation_required`
   либо произвольным кодом — для последних показывается текст сервера («Перенос отклонён: …»);
   отдельного кода `schema.move.feeder_*` в API E-2 нет.
4. **Touch-устройства:** HTML5 drag&drop по-прежнему не работает (ограничение E-1), для них остаётся
   клик «в центр»; подсказки таймаутов на тач не влияют.
5. Подсказки не перекрывают кнопки: drag-подсказка — `bottom-24` (над нижней навигацией),
   опасность — `top-14` по центру, обе `pointer-events-none`; визуально проверяется в §4.
