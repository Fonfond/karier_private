# Фикс создания связей (links) и UX соединения

## Причина 422

В Спринте 27 у узлов появились боковые порты-хэндлы с идентификаторами
`r-out`, `b-out`, `t-in`, `l-in` и т.д. При протяжке связи React Flow отдаёт
идентификатор **хэндла**, и он попадал в `pending.sourceHandle`.

Далее `connect()` отправлял его как есть:

```ts
from_port_id: pending.sourceHandle   // "b-out"
to_port_id: pending.targetHandle     // "t-in"
```

Pydantic ждёт `UUID`, поэтому сервер отвечал:

```
422 Input should be a valid UUID, invalid character: found `o` at 3
```

Проверено запросом: payload с `"from_port_id": "b-out"` → 422, с реальным UUID порта → 201.

## Что исправлено

### 1. Разбор портов на схеме

Добавлен `resolvePorts(connection)`:

* находит узлы `source`/`target` в графе;
* если хэндл — UUID порта, берёт его;
* если это боковой хэндл (`b-out`, `t-in`, …) — берёт первый подходящий порт узла
  (для источника `out`/`io`, для приёмника `in`/`io`);
* возвращает **UUID портов**, которые и уходят в `POST /api/links`.

### 2. Клиентская валидация до отправки

Проверяется до открытия формы связи:

| Проверка | Сообщение |
|---|---|
| нет выходного порта у источника | «У объекта «X» нет выходного порта» |
| нет входного порта у приёмника | «У объекта «X» нет входного порта» |
| направление не OUT → IN | «Соединять можно только выход со входом (OUT → IN)» |
| разные напряжения | «Напряжения не совпадают: 6 кВ и 0.4 кВ» |

На карте (режим «Связать») те же проверки выполняются в `dropLinkDrag` перед открытием формы.

### 3. Понятные ошибки вместо «422»

`api.ts` получил `normalizeProblem()`: ответ FastAPI с массивом `detail`
превращается в читаемый текст и `fields`:

```
Проверьте параметры связи — from_port_id: Input should be a valid UUID…
```

* На схеме ошибка показывается красным тостом справа сверху с кнопкой ✕.
* На карте — фиксированный тост по центру сверху (не перекрывает кнопки).
* Если сервер вернул бизнес-ошибку («Напряжения не совпадают», «Неверное направление
  портов»), показывается её текст.

## Проверки

| Проверка | Итог |
|---|---|
| `POST /api/links` с `"b-out"` | 422 с понятным текстом (воспроизведено) |
| `POST /api/links` с UUID портов | 201, связь создана и удалена после проверки |
| `tsc --noEmit` | без ошибок |
| `vite build` | успешно |

## Файлы

* `src-v2/src/lib/api.ts` — `normalizeProblem` для 422.
* `src-v2/src/components/map/SchemaView.tsx` — `resolvePorts`, валидация, тост.
* `src-v2/src/pages/MapPage.tsx` — проверка напряжения/направления, тост ошибки.

## Осталось

* Сменить порт у уже созданной связи через UI нельзя (редактор меняет тип/марку/длину/состояние).
* При автоподборе берётся первый подходящий порт; при нескольких выходах нужен выбор в форме —
  можно добавить селект портов в редактор связи.
