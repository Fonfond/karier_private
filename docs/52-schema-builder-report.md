# Визуальная сборка схемы с привязкой к реестру — отчёт

Версия 1.1 · 24.11.2026 · миграций не потребовалось (голова `0014_schema_snapshots`)

> Версия 1.1: добавлен раздел о браузерной проверке (§2–§4). В 1.0 функция была
> реализована, но в живом браузере добавление контура/ячейки не работало — ниже
> разобраны шесть причин и подтверждение исправлений.

## 1. Что было и чего не хватало

«Виртуальных» узлов на схеме не было: блоки, ячейки и перемычки уже создавались
как записи `gis.assets`/`gis.links`:

| Возможность | Реализация |
|---|---|
| Библиотека блоков (ПС, БКРУ, КТП) | `POST /api/schema/blocks/{code}/instantiate` — родитель и ячейки пишутся в реестр |
| Ячейки блока | `POST /api/schema/assets/{id}/cells` — объект с `parent_id` и `schema_block_id` |
| Перемычки | `POST /api/schema/assets/{id}/jumpers` — связь `jumper` внутри блока |
| Связи «ячейка → ячейка», отходящие | режим связей в редакторе, `POST /api/links` |
| Раскладка | `PUT /api/topology/layout` |

Добавлено в 1.0:

* `POST /api/schema/assets/{id}/place` и `DELETE …/place` — поставить существующий
  объект реестра на схему и снять его обратно (без дубля);
* `POST /api/schema/contours` — прямоугольный контур: объект в реестре
  (`attrs.block_code=contour`, размеры) + блок на схеме;
* ячейка принимает локальные `x`/`y`; тип подбирается резолвером
  (`cell` → активный аналог «ячейка» → любой активный несоставной);
* контуры попадают в `blocks` графа (даже без ячеек) с `kind/width/height`;
* на фронтенде — панель «+ Добавить» (реестр / тип / контур) и история Undo/Redo.

## 2. Браузерная проверка: что мешало добавить контур и ячейку

Проверка шла на изолированном стенде: Vite 5175 → API 8002 → **тестовая**
`karier_test_db` (рабочая `karier_db` не затрагивалась). Инструмент — headless Edge
через `puppeteer-core`, со сбором `console`, `pageerror`, упавших запросов и ответов
`4xx/5xx`, плюс скриншоты на каждом шаге.

Найдено и исправлено **шесть** причин:

| № | Что не работало | Причина | Исправление |
|---|---|---|---|
| 1 | Контур/блок не появлялся вообще | В `schema_graph.build_graph_out()` контейнеры (у них есть `attrs.block_code`) были исключены из `nodes` «чтобы не дублировать блок». Но редактор строит узлы ReactFlow **только из `nodes`** — контейнер не во что было отрисовать. Это же ломало и библиотечные блоки (ПС/БКРУ/КТП): они пропадали со схемы | Контейнеры снова попадают в `nodes` (и остаются в `blocks`); дубля нет — блок-ветка `AssetNode` рисуется по `data.block` |
| 2 | Кнопки «+ Добавить» не было на экране | Она была внутри блока `{editMode ? …}`, а режим редактирования по умолчанию выключен — панель инструментов скрыта | «+ Добавить» и «Снимки» вынесены в нижнюю панель, видимую без режима редактирования |
| 3 | Клик по плавающей кнопке в правом верхнем углу не открывал панель | Кнопка физически перекрывалась панелью вкладок карты (`elementFromPoint` показывал чужой `div`), клик уходил в неё | Кнопка перенесена в нижнюю панель; перекрытие устранено |
| 4 | Ctrl+Z после добавления ячейки выдавал `409 block.last_cell` | Защита «нельзя удалить последнюю ячейку блока» применялась и к контуру, где ячейка одна | Для контура (`block_code=contour`) удаление единственной ячейки разрешено; для библиотечных блоков защита сохранена |
| 5 | Элемент создавался, но «ничего не добавилось» | Контур ставился в центр вида (`schema_x≈8260`), а камера не двигалась — элемент оказывался далеко за экраном | После создания/постановки вызывается `fitView` на новый узел (два прохода: сразу и после перерисовки), в статус пишется подтверждение |
| 6 | В консоли всегда была ошибка `401 /auth/refresh` | На старте приложение всегда пробовало восстановить сессию, даже когда cookie ещё нет | Подсказка `localStorage['karier-session']`: refresh вызывается только если сессия была; ставится при входе, снимается при выходе/неудаче |

Дополнительно: карточка объекта больше не открывается сама после создания контура
(фокус только подводит камеру, `onSelect` не вызывается) — иначе она закрывала
только что созданный элемент.

```powershell
# 1. Тестовый API на тестовой БД
cd C:\karier\karier\backend-v2
# Пароль в документации не хранится: DSN с паролем — в backend-v2/tests/.env.test
# или в backend-v2/.env (оба файла в .gitignore).
$env:DATABASE_URL = (Get-Content .\tests\.env.test | Select-String '^TEST_DATABASE_URL=').Line -replace '^TEST_DATABASE_URL=',''
.\venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8002

# 2. Фронтенд с прокси на 8002 (конфиг-харнесс лежит в src-v2)
cd C:\karier\karier\src-v2
node .\node_modules\vite\bin\vite.js --config .\vite.test.config.mjs   # порт 5175

# 3. Сценарий в headless Edge (логин, контур, ячейка, Undo/Redo, F5)
cd C:\karier\.local\browser
node check-schema.mjs
```

Важно: правка файлов во время работы Vite на Windows иногда роняет dev-сервер
(`EBUSY` на своём временном файле) — после правок перезапускайте Vite
(или `stack-start.cmd`), это описано в §17 основного отчёта.

## 6. Ограничения и следующий шаг

1. **Контур не рисуется мышью** (протягиванием): размеры задаются в форме, затем
   блок двигается как обычный узел.
2. **Контур без ячеек** — пустой пунктирный прямоугольник, это ожидаемо.
3. **Логические линии (`lines`)** из интерфейса не создаются: отходящая связь —
   это `link` (кабель/ВЛ/шина).
4. **Тип ячейки** подбирается автоматически; явный выбор в диалоге ячейки — улучшение
   на будущее.
5. **Undo/Redo живёт до перезагрузки страницы** — история хранится в памяти
   компонента, после `F5` начинается заново (данные при этом сохранены).
