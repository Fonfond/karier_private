# Спринт 28. Группировка «ПС → ячейки» (этап 1)

## Что сделано

### Бэкенд

* `POST /api/asset-groups` — собрать выбранные объекты в группу:
  `{parent_type_code, name, child_ids, x, y}`.
  Создаётся родительский объект выбранного типа (автоматически), у детей
  проставляются `parent_asset_id`, `schema_block_id` и локальные координаты.
  Родителю добавляются порты `IN-1`/`OUT-1`, чтобы к нему можно было подключить линию.
* `POST /api/asset-groups/{id}/ungroup` — разъединить: дети снова самостоятельные,
  родитель мягко удаляется.
* В краткую карточку объекта добавлено `grouped` — признак «входит в группу»,
  и `parent_id`.
* Граф схемы отдаёт группу в `blocks[]` с `block_code = "group"` — существующий
  рендер блоков рисует рамку с подписью и дочерние объекты внутри без изменений.
* Аудит: `asset.grouped` / `asset.ungrouped`.

### Фронтенд

* **Реестр:** режим «Выбрать» (чекбоксы в таблице и карточках), кнопка
  «Собрать в группу», модалка с выбором типа родителя и названием.
  Фильтр «вложенные» — по умолчанию дети групп скрыты, при включении видны.
* **Карта:** объекты с `grouped = true` не отображаются — видна одна иконка ПС.
* **Схема:** группа приходит как блок: рамка, заголовок (имя группы/тип),
  ячейки внутри сеткой, внешние связи — через порты родителя.

## Проверено

| Проверка | Итог |
|---|---|
| Создание группы через API | `201`, 3 объекта стали детьми |
| `GET /api/topology/graph` | группа в `blocks[]`, `children: 3`, `block_code: "group"` |
| `GET /api/assets` | у детей `grouped: true` |
| UI-сборка (`tsc`, `vite build`) | без ошибок |

## Ограничения

1. Дети группы **не отображаются на карте** (это и требовалось), но их карточки
   доступны только через карточку группы: отдельного списка состава в UI пока нет.
2. Связи, которые были у отдельных ячеек до объединения, на схеме пропадают —
   их нужно переподключить к портам группы. Автоперенос связей — следующий шаг.
3. Разъединение пока доступно только через API (`/asset-groups/{id}/ungroup`),
   кнопка в интерфейсе не добавлена.
4. Типы с подтипами: иерархия используется как подсказка при выборе родителя,
   жёсткой проверки «дочерний тип → родительский тип» нет (можно собрать любые объекты).
